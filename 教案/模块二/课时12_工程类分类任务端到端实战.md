# 课时 12：工程类分类任务端到端实战

## 目标

1. 在高压时间限制下，把模块二前五节课的理论和工程骨架压缩成一次真实交付。
2. 学会围绕工程类数据集快速完成数据、模型、优化器、日志、可视化与报告的最小闭环。
3. 用完整训练记录而不是单个最终准确率来评价一次实验。
4. 学会识别过拟合拐点、数据偏差与 bad case，并给出下一轮迭代方案。
5. 形成“先跑通可信 baseline，再做复杂优化”的工程纪律。

## 推导

### 一、端到端项目不是拼代码，而是拆问题

一个最小工程任务至少要拆成六个部分：

1. 数据读取
2. 模型构建
3. 损失与优化器
4. 训练与验证
5. 日志与可视化
6. 报告与复盘

这节课要求学生把前面学到的每个概念都映射到一个具体环节里，而不是停留在局部知识点。

### 二、为什么 baseline 必须先行

复杂模型和复杂增强只有在最小闭环已经可信时才有意义。

课堂重点：

1. baseline 的价值不是成绩高，而是建立可靠参考系。
2. 没有 baseline，后续每次改动都无法判断是“真的有效”还是“偶然波动”。

### 三、工程类分类任务的典型难点

以混凝土裂缝分级、建筑材料识别、结构缺陷分类为例，常见问题包括：

1. 类别分布不平衡
2. 纹理细粒度差异大
3. 背景噪声强
4. 标签边界模糊
5. 样本量有限

因此学生要学会：

1. 先确认问题属于“数据稀缺”还是“表达不足”。
2. 先查类别分布与 bad case，再决定是否增加模型复杂度。

### 四、过拟合拐点的解释义务

课程要求学生不只交一条曲线，而要解释：

1. 何时出现训练验证分叉
2. 为什么出现
3. 下一轮该优先改什么

这意味着实验报告必须具备：

1. 时间轴
2. 指标轴
3. 现象到原因的解释链

## 实操

### 任务一：30 分钟跑通工程类分类 baseline

要求学生：

1. 选用一个工程背景分类任务。
2. 在限定时间内完成：
   - 数据读取
   - 模型定义
   - 训练脚本接入
   - 指标输出
3. 最终必须得到：
   - 可复现训练记录
   - 验证集指标
   - 曲线图

建议使用文件：

- `模块二_pytorch与深度学习训练闭环/代码示例/02_分类训练样例_train_classifier.py`
- `模块二_pytorch与深度学习训练闭环/代码示例/06_微型Trainer模板_mini_trainer.py`
- `模块二_pytorch与深度学习训练闭环/代码示例/07_AMP与梯度累加训练脚本_amp_accum_train.py`

### 任务二：输出完整训练记录

要求：

1. 保存每轮：
   - train_loss
   - val_loss
   - val_acc
   - lr
2. 输出至少一张训练曲线图。
3. 保存最佳 checkpoint。

### 任务三：做一次最小 bad case 诊断

要求学生：

1. 抽出最典型错误样本。
2. 至少分析三个问题：
   - 是否类别混淆
   - 是否纹理过细
   - 是否训练集样本覆盖不足
3. 给出下一轮迭代建议。

### 任务四：撰写第一版实验报告

要求：

1. 说明任务背景和数据特点。
2. 记录模型、优化器、超参数和训练设置。
3. 解释验证集过拟合拐点。
4. 给出下一轮优化路线。

## 验收标准

1. 必须在限定时间内跑通一个完整分类任务闭环。
2. 提交物必须包含训练记录，而不是只交最终准确率。
3. 必须保存 checkpoint、曲线图和实验说明。
4. 必须完成至少一次 bad case 分析。
5. 实验报告中必须明确指出验证集拐点和可能成因。
6. 必须体现出“先可信 baseline，后复杂优化”的工程纪律。

## 当堂交付物

1. 一份工程类分类 baseline 代码与训练日志。
2. 一份完整训练曲线图。
3. 一份最佳 checkpoint。
4. 一份 bad case 分析记录。
5. 一版实验报告草稿。
